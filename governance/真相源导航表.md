## 三、按事实类别确定权威来源

| 事实类别 | 唯一权威来源 | 其他位置的职责 |
|---|---|---|
| 系统目标架构与治理规则 | ZivenLab 对应治理文档 | 组件文档引用；运行时是否生效另需验证 |
| 系统当前实现地图与跨仓库差距 | ZivenLab `governance/现状架构.md`、`架构差距矩阵.md`（汇总层） | 作为索引/总结；不得覆盖组件证据 |
| 组件实际实现、工具注册与调用路径 | 对应仓库当前目标分支的源码、配置、注册表及可复核测试证据 | ZivenLab 记录摘要、证据等级与待核差距 |
| 数据库实际结构 | 当前目标环境的实时 Schema | GitHub 文档记录语义、规范和变更历史 |
| 身份与长期不可变约束 | 云端 `🧬/我是谁` | 角色卡是宿主投影 |
| 当前工作状态与下一步 | 云端 `⚙️/当前工作检查点` | ZivenLab 驾驶舱是项目治理视图，不得成为平行状态副本 |
| 跨会话恢复流程 | 云端 `⚙️/恢复协议·Session Bootstrap SB-1.0` | 各宿主实现/适配；实际生效需独立验证 |
| 文档定位 | 本导航表 | 只负责指路，不创造或覆盖事实 |

**生效状态必须分开标注**：已定义（权威文档存在）≠ 已接入（有真实加载/调用路径）≠ 已验证（有可复核测试证据）。不得把文档写好表述成运行时已生效。

## 五、失忆自救三连（换框/找不到时的固定动作）

## 六、核心代码入口与模块职责（仓库 `wovowx/mcp-memory`）

| 入口/目录 | 职责边界 | 当前注意事项 |
|---|---|---|
| `src/index.js` | Cloudflare Worker HTTP 入口、路由、定时任务、上传/运维端点 | 聊天室相关路由保留但处于暂停范围；唤醒链路不排查、不修复 |
| `src/modules/mcp_router.js` | MCP initialize / tools/list / tools/call 与工具分派 | 工具定义、Supabase 注册表与运行时分派并非同一层；`serverInfo.version` 与 `package.json` 版本存在差异，待核 |
| `src/tools/memory_unified.js` | 记忆读写、检索、导入导出等统一入口 | `search_history` 缺表但代码仍有依赖；静态代码已确认更新事件与 memories 写入会检查 HTTP 状态，但创建/软删除/重命名/移动尚未形成完整生命周期事件链；运行时行为仍需测试 |
| `src/tools/category.js`、`src/tools/data.js` | 分类操作与记忆数据导入导出 | 与统一记忆入口存在职责交叠，需先核对调用契约与审计一致性，不先合并 |
| `src/tools/database.js` | Supabase 数据库通用操作 | 用户已明确无需深挖；只在需要时核对职责/路由 |
| `src/tools/github_v64.js` | 当前 MCP Router 实际使用的 GitHub 工具实现 | 不要误把 `github.js` 当作当前路由实现；高风险分支操作必须遵守审批边界 |
| `src/tools/ai.js`、`cf_proxy.js`、`chat*.js` | AI/代理与聊天室相关工具 | 部分源码读取结果未完整确认；`chat*.js` 属暂停子项目，不在当前主线深挖 |
| `src/modules/agent_runtime/` | Chat2API 客户端、上下文解析、事件处理、MCP 客户端、watchdog 与 wake dispatcher | Chat2API 等共用模块仍属于主系统；唤醒链路单独暂停，不将整个 Runtime 误归聊天室 |
| `src/modules/execution/` | 执行会话管理 | 有执行 API/模块入口，实际使用强度与数据库状态待核 |
| `src/modules/patch_engine.js` | Patch Proposal 校验/应用及自测 | 当前仅确认源码存在，未声称已执行自测 |
| `src/utils/` | helpers、response、search、skills、storage 等通用能力 | `helpers.js` 与 `response.js` 有重复错误响应实现；`search.js` 依赖缺失的 `search_history` |
| `src/skills/` | Markdown 形式的能力说明与流程 Skill | 不等同于 Supabase `skills` 表里的工具注册/元数据 |
| `src/public/` | Worker 提供的静态页面 | `memory-universe` 路由读取 GitHub main 上的页面文件，需注意分支来源 |
| `scripts/check.mjs`、`tests/learning/` | 静态语法/相对导入检查与学习回归工件 | 静态检查不等于端到端测试；聊天室 webhook 测试不属于当前主线 |
| `package.json`、`wrangler.toml`、`.github/workflows/` | 包版本/脚本、Worker 配置、CI 与 Pages 发布 | README 路径描述与实际目录不一致；Pages 发布目录意图待核 |
| Supabase 表组 | 持久化记忆、平台注册、执行、协作、文件、会话绑定与暂停聊天室数据 | 当前工具枚举观察到 25 张（含 2 张测试表）；历史 schema dump 为 23 张业务表，需同口径重生成后再对齐 |

> 推荐阅读顺序：`src/index.js` → `src/modules/mcp_router.js` → 对应 `src/tools/` → 关联 `src/modules/` / `src/utils/` → `tests/` 与 CI。代码地图说明职责，不代替真实调用验证。

## 七、导航表维护规则
- 本表负责“去哪里找”；`资产全景.md` 负责资产索引；具体行为以当前代码、实时数据库与可复核测试证据为准。
- 历史数字、文档描述、源码实现、运行结果发生冲突时，明确标出差异，不自行猜测或把推断写成事实。
- 暂停不等于废弃。聊天室及唤醒链路保持暂停标记，保留现有资产，不在本轮移动、删除或修复。
- 后续待办：逐项核验文档交叉链接和已知差异；不要把本导航表当成代码运行状态或测试通过证据。
