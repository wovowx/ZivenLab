## 二、GPT 讨论结论（2026-10-17 采纳）

### 最该先做什么：**先建清单**
> 先把所有对象的用途、依赖、活跃状态、现有功能基线盘清，再动遗留清理/记忆归位/skill 合并——避免误删依赖或破坏可用功能。

### 整理的核心坑 + 原则（防踩坑）
> 最容易踩的坑：把"看起来没用/内容相似/暂时没调用"**误判为可删可合并**，导致隐式依赖断裂、历史丢失、重复被错误合并。
>
> 原则：**先查依赖 → 先备份 → 先做可逆变更 → 每次只改一小批 → 回归测试通过再继续 → 未经验证不删/不覆盖/不合并。**

## 四、整理升级计划（分阶段、每步可验收）

### 阶段 0 · 建资产清单（GPT 指·最该先做）—— 先立"我们到底有什么"的唯一索引
- 产出 `资产全景.md`：每个资产标「在哪 / 干什么 / 状态：在役/遗留/废弃/升级」
- 对应架构：真相源导航表 + 唯一路径。**什么都不删，先盘清。**

### 阶段 1 · 清遗留（低风险，先做不心疼的）—— 只归档，不删除
- 聊天室 common-ground/ + chatroom/ → **归档**（如 git 分支/archive 目录移出主线，保留可追溯）
- 数据库确认 knowledge 废弃 → 移除（先查依赖）；空表补 DDL 存档或标记
- 原则：**先备份、可逆、每次一小批、回归通过再继续**

### 阶段 2 · 归位记忆库（治 64% 默认堆积）
- 179 条按新分类体系归位；拆碎的单条分类合并
- 对应架构：记忆层"分层记忆 + 唯一路径"

### 阶段 3 · 合并 skills（治职责重叠）
- 图片媒体统一收进 agnes/image_upload；多余入口下线或标 deprecated
- 对应架构：治理层"唯一路径 + 强制路由"

### 阶段 4 · 升级（旧的升级成符合整体架构的）
- 数据库按 5 域 + 新记忆层规则对齐
- 呈现层 memory-planet 接进整体架构
