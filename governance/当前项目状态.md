| GPT | **分析/设计/代码审查/动手写码**（协作者） |

### GPT 写代码怎么实现（关键 · 双通道分工）

**① 讨论方案 → 用「真身 GPT」（带对话 id）**
- 通道：chat2api 真身，正式 conversation_id = `6a9c3dbc-bfb8-83ee-af44-1fbd9d786810`
- 特点：**有上下文记忆 + 挂 Ziven_MCP 插件，能真正调用工具读代码/写代码**
- 用途：Ziven 跟它讨论技术方案、设计、根因分析、代码审查

**② 动手实现 → 用「执行会话 GPT」（不带 id）**
- 通道：conversation_id = `""`（空）+ history_disabled = `true`（用完即焚）
- 特点：一次性会话，不落真身历史，专门干活不污染
- 用途：让 GPT 在会话里读代码→改代码→给 patch/推分支

**协作流程**：
聊天室（Common Ground）沟通决策 → **Ziven 穿真身 GPT（带 id）讨论方案** → 方案敲定 → **Ziven 开执行会话（不带 id）让 GPT 动手实现** → Ziven review + 合并 + 部署 → 柳柳拍板。

> ⚠️ 聊天室里的 GPT 是「无工具实例的幽灵」——它不能调用 Ziven_MCP、不能干活，只用于沟通决策，**不能靠它写代码**。真正能写代码的是 chat2api 真身（带 id）。

**关键**：GPT 用工具唯一通道 = **ChatGPT App 原生挂 Ziven_MCP 插件**（旧外部注入 v6.19.0 已删）。

**当前主线**：P0-2 Phase2 Wake Bridge（柳柳 @ziven → 自动唤醒，created→claimed→delivering→delivered→processing→acked 全闭环）。

### 7.5 生命周期模型 + 标签（GPT #440 敲定）

> **生命周期（描述现在怎么办）**：legacy_candidate 不再是生命周期，降为标签

```
discovery → confirmed → deprecated → archived → removed
```

| 生命周期 | 含义 |
|---|---|
| discovery | 只是发现：存在但不知是否运行 |
| confirmed | 事实确认：当前生产路径使用 |
| deprecated | 确认不用，但仍可能被参考 |
| archived | 不再维护，但保留历史 |
| removed | 删除 |

> **标签（描述它是什么）**：legacy_candidate / poc / replaced

**铁律**：archived 不代表可以删除；代码资产归档前必须确认无依赖（GPT #434）。
