## 验收与推进规则

1. 每行仅在证据满足验收条件后改为完成；文档已写不等于代码问题已修复。
2. 运行时结论保留真实调用/测试结果；没有命令输出和退出码，不写“通过”。
3. 缺权限或宿主能力时，记录阻塞和可执行任务，不用推测补结果。
4. 数据库 schema、生产代码、部署或 main 分支变更须遵守既有审批边界。
5. 每次代码结构调整都检查复用性、职责边界、真实扩展路径和兼容影响；不为抽象而抽象。
6. 每次代码结构调整都检查复用性、职责边界、真实扩展路径和兼容影响；不为抽象而抽象。

## search_history / suggest 验证基线（执行契约）

**范围仅限测试与证据收集，不改生产代码、不建表、不删功能。** 当前代码入口为 `src/utils/search.js`，调用方在 `src/tools/memory_unified.js`。

| 场景 | Mock 响应/操作 | 预期契约 | 需要记录的实际结果 |
|---|---|---|---|
| 空白关键词 | 调用 `recordSearchKeyword(env, "  ")` | 不发起 fetch；不抛错 | fetch 调用次数为 0 |
| 已有历史 | GET 返回 200 + `[{keyword:"alpha",count:2}]` | PATCH 对应 keyword，count 增至 3；keyword 规范化为小写并 trim | 请求 URL、method、body |
| 无历史 | GET 返回 200 + `[]` | POST 新记录，keyword 小写/trim，count=1 | 请求 URL、method、body |
| 建议正常结果 | GET 返回 200 + `[{keyword:"alpha"},{keyword:"alpine"}]` | 返回 `["alpha","alpine"]`；prefix 需 trim/小写，查询限制为最多 20 条 | 返回值、fetch URL |
| 缺表/HTTP 非 2xx | GET 返回 404/500，body 分别模拟 JSON 错误对象与合法数组 | 搜索主流程不因历史记录失败而中断；建议返回空数组；不得把非 2xx 当成有效历史并据此 PATCH/POST | status、body、fetch 调用序列、异常/返回值 |
| 空建议 | GET 返回 200 + `[]` | 返回空数组；调用方应显示正确空态文案 | 最终工具响应/空态文案 |
| 非 JSON/网络拒绝 | fetch reject 或 `resp.json()` reject | 辅助历史功能失败应被隔离；建议返回空数组，不应让主搜索失败 | reject 类型、最终工具响应 |

**静态已知风险（需要由测试验证，不预先判定修复成功）：**
- `recordSearchKeyword` 未检查 `resp.ok`，并吞掉所有异常；GET 失败后可能继续尝试 POST，PATCH/POST 的非 2xx 也可能被静默忽略。
- `getSearchSuggestions` 未先检查 `resp.ok`；若非 2xx 返回数组 JSON，可能被当作建议结果；错误对象则可能因缺少 `map` 被 catch 后转成空数组。
- 调用方空态表达式存在字符串拼接与 `||` 优先级问题，预期兜底文案可能不会出现。
- `package.json` 当前只有 `npm run check`（`node scripts/check.mjs`）；`scripts/check.mjs` 仅做 `src/**/*.js` 语法与相对 import 完整性检查，不跑行为测试。现有 `tests/webhook_idempotency_test.mjs` 采用独立 `.mjs` 脚本、手动断言与 `process.exit(fail ? 1 : 0)`，但 import 写死 `/tmp/mm2/...`。若新增 search 行为测试，建议沿用独立脚本/明确非零退出码，改用相对 import（如 `../src/utils/search.js`），并用 `node tests/search_history_test.mjs` 单独执行；不要把 `npm run check` 当行为测试。
- 验证必须分别记录 `npm run check` 的真实退出码和测试文件的真实退出码；如果需要 MCP endpoint 验证，应单独记录请求条件与结果，不能用静态检查替代。
