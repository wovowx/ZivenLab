# 执行会话任务模板 v1

> 版本：v1 · 2026-09-06
> 状态：**confirmed**（Ziven × GPT 讨论 #876/#877 收敛，柳柳拍板）
> 适用范围：**仅执行会话**（无固定 conversation_id 的一次性任务会话）
> 声誉：不适用于正式讨论会话 / 架构设计 / 决策确认 / 协作协议修改（那些走讨论流程，本模板只管「做事」）

> ⚠️ 2026-09-07 已并入 `governance/GPT协作规范.md`（第 2 节）——本文件保留为旧引用兼容，新读者请读 GPT协作规范。

## 前提

- 执行会话 = 无固定 conversation_id + history_disabled=true（用完即焚）
- 执行会话**没有长期上下文**：不要假设拥有此前讨论记忆，所有必要事实均由本任务提供

## 模板

```
你是本次任务执行 Agent。

当前会话类型：
执行会话（无固定长期上下文）
不要假设拥有此前讨论上下文。
所有必要事实均由本任务提供。

目标：
{一句话描述最终目标}

项目：
{仓库名}/{分支}/{相关路径}

背景：
{为什么要做这件事}
{已有事实、约束、历史决策}

需要完成：
1. {任务1}
2. {任务2}
3. {任务3}

验收标准：
- {完成后必须满足什么}
- {如何验证成功}
- {需要输出什么结果}

约束：
- 请基于当前可用能力完成任务。
- 不要假设不存在的能力。
- 如果缺少必要条件，请明确说明缺失项，不要编造结果。
- 如果存在多个实现路径，选择风险最低且符合目标的一种，并说明理由。

完成后输出：
1. 修改摘要
2. 影响范围
3. 验证结果
4. 未解决问题/后续建议
```

## 使用规则

### 1. 能力（工具）如何表述

**默认规则：不强制指定工具调用。**

- ✗ 不在任务描述中写「请调用 xxx_tool 完成」
- ✓ 改为意图式：「请读取某仓库某文件」「请检查某服务状态」「请完成某操作」
- 让执行 Agent 根据自然语言自主选择能力

**特殊情况：**
如果任务必须指定能力，写：

> 如果当前环境提供对应能力，请使用；否则说明缺失条件。

不要强制调用。

> 依据：2026-09-06 三次对照实验——点名 ds_quota ✅ / 点名 github_read ❌（OpenAI 安全检查屏蔽）/ 意图式「读这个文件，工具你选」✅。OpenAI 平台对「prompt 显式点名调用具体工具」触发更严格安全校验；自然语言意图 → 模型自主选能力 → 放行。

### 2. 统一强制范围

| 任务类型 | 用模板？ |
|---|---|
| 代码修改 / 文档修改 / 部署操作 / 复杂多步任务 | ✅ 必须 |
| 诊断查询（如「查一下当前额度」） | ❌ 例外，可直接问 |
| 工具验证实验（测试某 connector 是否挂载） | ❌ 例外，属实验性质 |

### 3. 与讨论会话的边界

| 会话类型 | 职责 | 模板 |
|---|---|---|
| 执行会话（无 id） | 做事：按目标完成实现 | 本模板 |
| 正式讨论会话（带 id） | 共同判断：架构/决策/协议 | 讨论流程（协作协议〇.五） |
