# 项目时间轴星系 · 写入与回顾规范（v1.0）

> - 版本：v1.0（2026-10-20 柳柳拍板）
> - 依据：柳柳 2026-10-20 拍板立项；GPT 2026-10-20 核心收敛；`记忆层存量归位规范`；`治理与记忆_最终需求`
> - 本性：把「现实中一个主体怎么演化」按有据时间组织成一条可回望的线；是**现有记忆体系的时间视图**，不是新记忆系统。
> - 首个试点：记忆星球（`⚙️/时间轴·记忆星球·index` + `001~006`）

---

## 一、定位与四者分家

> 判别分外重要，四种东西各属各的，不混装：

| 是什么 | 职责 | 谁来证明 |
|---|---|---|
| `memory_events` | 记忆**记录变更**账本（写入时间只能证明记忆何时变，**不能充当项目事件发生时间**） | append-only 触发器 |
| **时间轴事件** | 现实项目/主体**如何演化**（提出/失败/转折/交接/暂停/重启…） | 有据时间 + 证据出处 |
| 驾驶舱 milestones | **当前状态**（现在在哪、下一步什么） | 驾驶舱 |
| **时间轴** | 按有据时间**重组**的可回望的线 | 本规范 |

- **事件时间 ≠ recorded_at**：今天找回去年的事 ≠ 去年发生。recorded_at 由系统写，事件时间由证据支撑。

---

## 二、节点模型（一条时间轴由什么组成）

- **主体索引** `⚙️/时间轴·<主体>·index`：
  - 主体是谁 / 当前状态 / 事件节点入口（001~NNN）/ 一句话 / 关联记忆。
- **事件节点** `⚙️/时间轴·<主体>·001~999`：
  - 统一 value 块（见下），按时间顺序编号。

---

## 三、事件节点 value 统一块（模板）

```markdown
# <主体> · 事件 <NNN>｜<事件名>
- 事件类型：proposed|decision|milestone|blocker|turning_point|handoff|state_change|release|retrospective
- 事件时间：exact|range|unknown（描述具体到哪、缺什么）
- 时间依据 basis：user_explicit|source_dated|derived|unknown（derived 必附推断依据，允许被推翻）
- 证据 source_ref：原始出处（对话/文档/事件账本/PR-部署）
- 摘要：…
```

- **9 类事件类型**（不细分）：
  `proposed` 提出 / `decision` 决策 / `milestone` 里程碑 / `blocker` 卡点 / `turning_point` 转折 / `handoff` 交接 / `state_change` 状态变更（含暂停/重启）/ `release` 发布 / `retrospective` 复盘。

---

## 四、时间纪律（最重要）

- **事件时间与 recorded_at 严格分开**。
- **`unknown` 就标 unknown，绝不偷偷补精确**（如「8月15日」不擅自补年份；「最初提出」无记录就标 unknown）。
- **`range`** 写清描述 + 依据（如「约一个月，起止待核」）。
- **`derived`** 必须记录推断依据，允许被推翻；无从推断就用 unknown。
- 时间 precision 三值：`exact / range / unknown`。
- basis 四值：`user_explicit / source_dated / derived / unknown`。

---

## 五、写入规则

- **先查重**：主体是否已有 index？此事是否已建节点？有 → 更新原档，不新建散档。
- **一条节点一条记忆**：可独立引用、不整篇重写、不合并超长一条。
- **分类挂 `⚙️`**（项目/技术）；key 前缀带 `⚙️/` 以便归位。
- 编号按时间顺序连续；后续补节点不改旧编号。
- **联想只发现候选、不替时间轴编故事**：纯语义只能标「待核实」，不得写 exact。
- 改动节点走记忆 update 留痕（`memory_events` 记账本，事件时间仍与 recorded_at 分开）。

---

## 六、回顾规则

- 回顾 = 按节点时间排序重建「怎么走到今天」，每个节点能回到 `source_ref`。
- 没把握的时间如实标，不把推断当事实陈述。
- 不确定处回真相源核实，或标「待柳柳确认」，不自行补全。

---

## 七、新增/变更流程

1. 柳柳确认「主体 + 候选节点」→ 建 index。
2. 逐个核实节点时间与证据 → 建事件节点（unknown 如实标）。
3. 回顾验证：能按时间排列回顾 + 未知如实标注 + 节点能找到原始记录。
4. 边界：判断标准「未来的柳柳是否可能想知道这件事怎么开始」——未必只是项目型，持续性事项/重要事件型也可。
