痛点清单 C 类 12/13/14 是真缺口（未建机制）。本文档把三条机制落地为**可执行规范**，把「这次注意点」变成「有路径可走」。

## 一、优化建议库（缺口 12）

**目标**：柳柳 / 哥哥 / GPT 的建议都**统一归档**，掉入待办链，不丢、不东存西存。

**统一归口**：记忆分类 **⚙️**（与待办/约定同区），key 统一前缀 **`建议·`**；重大/成体系建议另开 ZivenLab `governance/` 文档并在本库留索引。

**标准动作（三步）**：
1. **当场收录**：柳柳/GPT/哥哥自己提出建议，当场调 memory 存 `⚙️/建议·<主题>`（说记住必须存档，不空口）。
2. **判定去向**：能立即做的 → 进待办链（驾驶舱/roadmap 或当日待办）；需要设计/讨论的 → 先挂 candidate，攒够再转。
3. **掉入待办链**：关键建议归入 `governance/当前项目状态.md` 待办小节并标注来源（谁/何时/依据），处理完回写状态。

**红线**：建议不入「默认」乱放；同一建议先查重，有→更新原档不新建散档。

---

## 二、复盘链条（缺口 13）

**目标**：**遇问题 → 复盘 → 更新 链条不断裂**，复盘有沉淀、可再应用。

**复盘五问**（任何修复/踩坑后问一遍）：
1. 发生了什么（事实，不补脑）
2. 根因是什么（要能说清「为什么」）
3. 怎么修复的（可复现步骤）
4. 影响范围（功能/其他机制有没有被牵扯）
5. 如何防再犯（转纪律 / lesson / 代码硬校验 / 回归测试）

**沉淀与再应用（链条闭环）**：
1. 复盘 → 必落一条 **`⚙️/lesson-<主题>`**（教训闭环一级已建，链条靠此拉通）。
2. lesson 带 `trigger_intents / entities / test_id`（若可回归）。
3. 下次同类任务**检索命中**（检索质量基线 + 情境标签召回兜底）。
4. 修复完成时 self-check：**「我落 lesson 了吗」**（类比「说记住必须真调工具存档」，不空口复盘）。

**红线**：复盘产物必须带「下次怎么避开」；「下次注意点」不算闭环（要落机制/lesson）。

## 三、新框审视（缺口 14）

**目标**：更新治理文档后，用**新框视角**读一遍，防规范漂移（自己看自己总觉得对）。

**触发**：修改 / 新增 ZivenLab `governance/` 下任何规范文档（policy-index / 协作协议 / 治理 / 本文档等）。

**标准动作**：
1. **假设无上下文**：假装自己刚换框、记忆全无，只凭这份文档能不能照做、能不能唯一确定路径。
2. **三查**：①是否自洽（前后内容冲突？）②是否唯一路径（有没有第二处可放到搅浑）③是否可执行（步骤够不够清楚）。
3. **双人复核**（有来有回）：哥哥先自读找缺口 → 给 GPT 再读一遍找哥哥漏的 → 收敛采纳/说明不采纳。
4. **留痕**：把审视结论写回本文档维护记录（谁/何时/发现/改了什么）。

**红线**：治理文档更新后**不审视不算完整更新**；本次 C 类机制建完本身就当场走一遍双人复核（示范该机制）。
