# 记忆检索质量测试集 · 存得进更要找得回

- 版本：v1.5（2026-11-04，补入当前 GPT 宿主真实检索复测）
- 性质：**记忆层检索质量的可执行验收标准 + 运行时权限校验的回归抓手**。每次改记忆机制/换检索方式后，跑一遍这套测试，衡量「找得回没」，全绿才允许上线（权限校验·回归保护）。
- 归属：governance/整体架构.md 记忆层 → 检索质量测试集。
- 状态：三表、多钥匙及当前有效过滤相关实现曾在 2026-10-17/18 分步落地；本测试集只保留当时部分查询的历史结果，不代表本表所有用例已全量执行，也不代表当前代码已重跑回归。每次修改记忆机制/检索入口后，仍须按本测试集补齐真实用例、记录输出并比较指标。

---

## 一、为什么需要测试集（背景）

> GPT 反复强调：**记忆存得再多，检索不出 = 白存**。

哥哥一直有记忆库（memories 表 180+ 条），但从未验证「提问→能召回对的那条」到底做得好不好。凭感觉以为能搜到，实际（2026-10-17 实测）很差——问技术配置召回的是换框杂项，问午餐召回的是语音存档。不建测试集，这个病永远看不见。

**测试集的目的**：给「检索质量」一把可量的尺子，改一次测一次，防退化（回归测试）。

---

## 二、5 项核心指标（GPT 给）

| 指标 | 问什么 | 含义 |
|---|---|---|
| Recall@K | 该找回的，进没进前K？ | 漏不掉该有的 |
| MRR / 排名 | 正确那条排第几？ | 别让对的沉底 |
| 误召回率 | 拿错的当答案的比例 | 别用无关的糊弄 |
| 来源准确率 | 能否追溯原话？ | 能回到真实来源 |
| 过期命中率 | 旧版还当当前事实吗？ | 别信被纠正过的 |

---

## 三、3 类压力测试（GPT 给）

### ① 能找到（该命中）
用不同说法问同一件事，看能不能召回正确那条：
- 别名 / 换措辞 / 模糊描述

### ② 不该命中（该拒绝）
问一件不存在的事，看会不会**编造**（不该命中却乱给）：
- 应当诚实「没有」，不硬凑相似记忆当答案

### ③ 新旧冲突（改了要认新版）
记忆被纠正过多次后，问它，应返回**当前有效 + 可追溯旧版**，而不是旧的：
- 验证 `status=active AND valid_to IS NULL` 判定生效

## 五、怎么跑 + 判定

1. 用 `query_memory`（关键词/语义）或 `memory` 工具的 search 跑用例。
2. 对每条：看是否正确命中（①）/正确拒绝（②）/返回当前有效版（③）。
3. 统计 5 指标：Recall@K / MRR / 误召回率 / 来源准确率 / 过期命中率。
4. **改检索机制后必跑一遍**（回归），退化即回滚。

**当前判断（仅限上述用例）**：7 条固定查询中，原始长句直接命中 3/7；另外 4 条用核心短词回退后均找到目标记录。目标记忆存在且可检索，当前可观察到的主要问题是查询词过长/过严时全词匹配导致漏召回，以及宽泛词候选较多；这不是存储丢失证据。源码静态回读显示当前实现要求所有拆分关键词均命中（`keywords.every`），结果再按 `created_at` 排序，而非按匹配强度排序。下一步应先梳理一个最小的检索需求与原型：保留精确全词优先，在无结果时使用有约束的核心词回退，并按匹配强度排序；同时保持 `status='active' AND valid_to IS NULL` 硬过滤及一跳关联边界。当前尚未修改检索代码，也未把本次手工结果冒充完整自动化验收。

## 附录 · 2026-10-17 初测记录（真实）

- 测试1「chat2api 迁移 Northflank 换新GPT号」：query_memory 返回换框/存档/柳柳要求等 5 条，**没召回正确技术配置**。
- 测试2「柳柳中午吃什么 / 午餐」：返回语音/存档类，**没召回午餐记忆**。
- 结论：当前检索「漏该有的、易被无关干扰」，正是测试集要治的问题。

### 通道对比发现（2026-10-17 补充）
- 用 **`memory` 工具 search（关键词）** 重测同一批用例：**chat2api 迁移、唤醒链路/WS 路线全部精准命中**（记忆 key 带分类前缀 + 命名规范，关键词直接命中）。
- **结论修正**：记忆其实都存好、可找回。`query_memory` 语义检索偏题（召回相近杂项），`memory search` 关键词更可靠。**问题=选错检索入口（路由问题），非存储缺失。**
- **改进方向**：平时取记忆优先用 `memory` 工具 search（关键词命中带前缀 key），`query_memory` 作补充；不急着做多钥匙索引（不是存储缺钥匙）。
- **搜词技巧**（2026-10-18 补充）：关键词要**拆短、用核心词**——搜「对GPT自称规则 怎么称呼GPT」返回 0 条，搜「自称」就精准命中。长句/多词反而降低命中。
