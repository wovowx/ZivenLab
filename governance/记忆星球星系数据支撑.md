# 记忆星球 · 星系数据支撑（V1）

> - 版本：v1.0（2026-10-20，Ziven 消化与 GPT 的讨论后定稿，柳柳授权选型）
> - 依据：柳柳星系模型（星系=关联点+星集、涌现式诞生、避免蜘蛛网）；网上参考（MemoryConstellations / constellation-engine：Hebbian 强化、Leiden 聚类、edge-decay）；GPT 讨论（三层分离、主归属唯一、轻量留升级空间、防蜘蛛网=结构约束）；记忆星球 v4【幸福碎片】初版设计（权限分工+随机回顾）
> - 定位：记忆星球 = 长期 AI 与主人共同成长记忆可视化的星系制体系。本规范定义**数据承载层（不改 schema）**，用现有 memories 多字段固定语义支撑星系模型，为记忆星球呈现做数据支撑。

## 一、三层分离
- **记忆层**：星本身 = 事实 / 时间 / 出处（已有）
- **组织层**：主归属星系 + 有据跨系关联 ← 本规范主体
- **激活层**：恰当时刻浮现 ← 幸福碎片（随机飞一个星系来一起回顾）、联想

## 二、权限分工（初版早已定）
- **Ziven 归档整理**（系统提议 + 主力整理）
- **柳柳：修改权 + 备注权**（重要组织决策最终由她点头）

## 三、字段语义约定（V1 · 不改 schema，但语义分明）
| 语义 | 字段 | 约定 |
|---|---|---|
| **主归属** | `entities[0]` | 稳定锚名 `锚:<slug>`（如 `锚:像人`），唯一；辅助实体从 `[1]` 起、不带 `锚:` 前缀；`unassigned` 星可无锚 |
| **备注**（柳柳备注权） | `value` 元数据区 `owner_notes` | 固定结构化边界；由一个「备注读写」动作解析；不与正文相混、不被语义检索当事实；改正文不误删备注 |
| **跨系关联** | `related_memory_ids` + `value` 的 `relations` 区 | ≤3 条；`relations` 写 `{类型, 证据}` 稳定可解析格式；正式类型=四类锚（project/event/person/theme） |
| **情境唤醒** | `trigger_intents` | 唤醒词 / 情感标签（支撑幸福碎片、联想） |
| **时间** | 正文有据时间 + `valid_to` | 事件时间与 recorded_at 严格分开；unknown 如实标注 |

> 关键共识：**不改 schema ≠ 不做数据建模**。约定要明确到写入、读取、校验、纠错、升级都有规则，否则只是把迁移成本埋进字段里。

## 四、防蜘蛛网（结构约束优先于算法）
1. 单一条件（共享标签 / 同人 / 相近时间 / 同轮检索 / 高相似）**只产生候选，不自动连线**；正式连线必带关系类型 + 证据
2. **连线预算**：主归属 1、普通星主动跨系关联 ≤3、自动激活跳数 ≤1
3. **宽泛锚**（如「重要」「长期」）设范围与边界，不无限吸收
4. **衰减边、不衰减事实**：区分「记忆有效性 / 关系可信度 / 关系使用价值」；低频但重要的经历不因少用而消失

## 五、归档纪律（Ziven 的约束）
- 归档必写好 `锚:`（主归属）；辅助实体不得冒充
- 改主归属必记旧值 + 原因，走 `memory_events` 账本可追溯
- 定期异常检查：缺锚 / 锚失效 / 多个候选锚 / 错误下标 / 重复关联
- 主人（柳柳）更正归档或备注，旧决定保留痕迹，可追溯

## 六、路线
- **V1**：本规范（受约束星系组织，现有字段承载）
- **V2**：可审计带权关系（有真实使用后；主归属迁移为 `membership` 型关系，锚建 UUID）
- **V3**：情境激活 / 聚类 / 扩散（记忆星球视觉起来后）
