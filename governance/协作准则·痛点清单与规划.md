## 三、能力-凭据-方法清单（哥哥的关键操作能力真相）

> 目的：防「之前能做到、换框/换环境后忘了怎么做」（柳柳第 11 条「忘记工具存在」的根治）——把关键能力的方法、凭据位置、路径固化在这里。

### Cloudflare（worker env 管理 · 2026-10-19 找回）

| 能力 | 凭据/方法 | 说明 |
|---|---|---|
| **管理 mcp-memory worker env（增删改 secret/变量）** | `/usr/bin/wrangler`（4.121.0）+ `CLOUDFLARE_API_TOKEN`（那把全权限 cfut_，已贴对话暴露，**待轮换**）+ `CLOUDFLARE_ACCOUNT_ID`（c04697fed53b74f26f520905b748932a） | 方法本源：记忆 `deploy/cloudflare-token-Wrangler-method`（2026-09-04 柳柳给哥哥创建的读写 API Token）。换框后曾丢失临时文件，靠这条记忆找回。 |
| **查/删 worker secret** | `wrangler secret put/list`；`/secrets/{name}` DELETE 端点 | 用 /tmp 临时 token 文件（600 权限、用完即删），绝不回显 token 值。 |
| **重部署让 secret env 生效** | `wrangler deploy`（重部署现有代码） | 改完 secret 必须 redeploy，否则工具读到旧值（build_logs Missing 的根因）。 |
| **查构建日志（build_logs）** | `cloudflare_build_logs` 工具；手动端点 `/accounts/{account}/builds/workers/{tag}/builds`（worker tag=`d9314c0892134f7581b9e9fcd15bfe5f`） | Builds API 需要 user-scoped token + **Workers Builds Configuration Edit** 权限（哥哥那把旧 cfut_ 缺它，一直 Invalid token）。端点要带 `/accounts/{id}` 前缀。 |
| **查部署记录（deploy_status）** | `cloudflare_deploy_status(verify_main=true)` | Deployments API 权限；部署后必查，VERIFIED 才收尾（柳柳铁律）。 |

**关键教训**：
- 同一把 token，不同 API 端点要求的权限不同（Deployments 与 Builds 不同，缺一个就 401）。
- 改 env 后```必须```re-deploy，否则运行中 worker 读旧值——「为什么改了一直不行」的常见根因。

## 四、mcp 仓库结构审计（B 线 · 2026-10-19 进行中）

### 结论（GPT 逐文件审计 · 2026-10-19 完成）

**核心发现：风险不只是文件数量，而是「旧版记忆路径可能绕过当前生命周期规则」+「旧版 GitHub 接口与新版参数契约不兼容」。优先解决这两点，比整理目录更有价值。**

| 文件 | 状态 | 判断 |
|---|---|---|
| `github.js` | legacy | 路由导入的是 `github_v64.js`；旧版仍含自己的 GITHUB_TOOL_DEFS。待退役候选（删前全仓扫引用） |
| `github_v64.js` | active | 路由导入它（github_edit/github_copy/写后校验）。**接口与旧版不兼容**（要求 content_url，旧版收 content） |
| `memory.js` | legacy | 旧记忆入口：读取不筛 status、删除是物理 DELETE |
| `memory_unified.js` | active | 软删除 + 版本递增 + memory_events 历史。作为唯一写入基线 |
| `chat.js` | active | 共享业务逻辑（被 HTTP 路由 + chat_mcp 复用） |
| `chat_mcp.js` | wrapper | MCP 适配层（校验+转发），不重复业务 |
| `chat_webhook.js` | active | Supabase Webhook（幂等/审计），与 MCP 入口职责不同 |
| `database.js` | active | 通用 Supabase 表查询/增删改 |
| `data.js` | active | 记忆 JSON 导入/导出；**但自带 memories CRUD 与 memory_unified 重叠（风险：绕过版本历史/软删除，导入记录元数据可能不完整）** |
| `cf_proxy.js` | active | 通过 worker env 调 Cloudflare API（高权限代理，需单独安全审查） |
| `ai.js` | active | Agnes 图像/视频能力（模型降级/错误诊断），与 cf_proxy 不同业务 |

**聊天三文件分工明确、不合并**；`database.js`/`data.js` 不同职责、保留分离；`cf_proxy.js`/`ai.js` 不通类、保留分离。**待退役：`github.js`、`memory.js`**（先扫引用+回归再删）。

**最小迁移顺序（分批、每批独立 PR + 回归 + 可回滚）**：
1. **记忆写入路径统一**：memory_unified 唯一主路径，消除 data.js 绕过版本历史的写入（最高优先）
2. **GitHub 旧版退役**：确认 github.js 无消费者 + 核对新旧 schema 后删
