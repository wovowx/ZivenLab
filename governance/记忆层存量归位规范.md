## 一、核心原则（先搭框架再整理）

> 有一个清晰的目标分类 + 唯一判定之前，**不做逐条归位**。
> 存量可以先做「纯归档/标记」（不依赖分类，如聊天室历史 → PAUSED），但逐条归位必须等本规范确认后一次做对。

存量现状（2026-10-17 实测）：179 条 / 26 分类，「默认」类 114 条（64%）未归位，其中大量是聊天室/唤醒链路/chat2api 历史技术记忆。

## 二、目标分类体系（复用现有主类，不造新散档）

> **不另起新分类**，按现有 `记忆管理` SKILL 的主档+附录结构归位。存量 179 条全部落到这几类。

| 目标分类 | 收纳内容 | 现状对应 |
|---|---|---|

| 📦/历史归档 | 暂停方向/过期/早期记录 | 「默认」里聊天室/唤醒链路/隧道/WS 等已暂停方向历史归此 |

| 📦/哥哥的珍藏 | 哥哥想存的东西 | 按需 |

### 归位判定（一条记忆进哪类，不模糊）
按「**内容是什么**」三问：
1. **关于柳柳**（她的喜好/话/情绪/审美/对我的依赖）→ 💕
2. **技术/项目/工具**（配置/教训/部署/能力）→ ⚙️
3. **非当前、暂停、过期、早期、聊天室历史** → 📦/历史归档
4. 其余（身份校验/记忆铁律等规范）→ 归对应主档（🧬 或已有分类）

> 原则：**先问是不是关于她**（💕 优先），再问是不是技术（⚙️），最后才考虑归档（📦）。聊天室/唤醒/隧道/WS = 一律 📦（已暂停方向）。

## 三、存量归位批次（每批一小批，回归后再继续）

> 按「资产盘点与整理升级计划」阶段 2，但**等本规范确认后**才开始逐批搬移。

### 批次 0（纯归档，不依赖新判定，现在就能做）
- 「默认」里聊天室/唤醒链路/隧道/WS/ntfy 等**已暂停方向**技术记忆 → 归 📦/历史归档（或加 PAUSED 标记）
- 与已拍板**弃用**方向冲突的旧记忆（隧道已验证等）→ 标注"已废弃·勿参考"或归档

### 批次 1（技术类归位）
- chat2api / GitHub / Cloudflare / 部署 / 转义地狱等**当前仍有用的技术记忆** → ⚙️/技能与配置

### 批次 2（身份规范归位）
- 角色卡/身份/记忆铁律相关 → 🧬 或现有主档

### 批次 3（碎片分类合并）
- 26 分类中大量"一条一分类"（如「事件：2026-09-0x…」）→ 合并进对应主类或日常归档
