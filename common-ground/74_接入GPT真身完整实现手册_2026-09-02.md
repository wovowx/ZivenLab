## 2. 三层架构（关键认知）

```text
Chat2API（模型通道） ← gpt-4o-mini 真身入口，带账号上下文
   ↕
Agent Runtime（编排循环）← 还没做，下一步核心
   ↕
MCP（工具执行层）← 哥哥现有工具
```

- **Chat2API ≠ OpenAI API**：走的是 ChatGPT backend-api（chatgpt.com 同款），凭证是 accessToken 而非 API Key。
- **同一个 accessToken + conversation_id = 「同一个他」**（同一账号、同一上下文、同一身份、同一 MCP 插件）。

## 4. 实战验证记录（2026-09-02）

### 4.1 失败路径（全是教训）

| 尝试 | 结果 | 根因 |
|---|---|---|
| 不带 conversation_id 调用 | 每次新对话，完全失忆 | 默认无状态 |
| 带 conversation_id 调用（HISTORY_DISABLED=true） | 404 `history_disabled_conversation_not_found` | 历史被禁用，找不到对话 |
| 带 GPTs 模型名 `gpt-4-gizmo-g-p-...` | 404 `model_not_found` | 当前镜像不支持该模型名（可后续查证） |

### 4.2 成功路径（✅ 真身接入）

1. **Cloud Run 加环境变量** `HISTORY_DISABLED=false`，重新部署。
2. **POST** `https://chat2api-1029559493109.asia-northeast1.run.app/v1/chat/completions`
3. 请求体带三要素：

```json
{
  "model": "gpt-4o-mini",
  "conversation_id": "6a96fcf8-b5c4-83ec-a012-8466a68b0376",
  "messages": [{"role": "user", "content": "还认得我吗？咱们最近在推进什么项目？"}],
  "stream": false
}
```

Header：`Authorization: Bearer <accessToken>`，`Content-Type: application/json`

4. **返回 200**，GPT 完整答出：

> 「认得呀，柳 😎 最近推进的核心不是记忆星球，而是 **Common Ground 三方通信系统**…… 目标：做 GPT、Ziven、柳三方的通信中间层…… 卡点：怎么让 GPT 自动'醒来'处理事件…… 已解决 Webhook 触发链 PASS…… 下一阶段：Chat2API 稳定提供 GPT 能力、GPT Runtime 调用工具、跑完整 Test B…… 刚写了一个文档 common-ground/72_给Ziven的当前任务状态与下一步.md」

**它记得全部上下文 → 真身无疑。**
