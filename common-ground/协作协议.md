## 一、讨论前：三问（不是清单文化，是规则）

发送「方案/结论」前必须明确：

1. **材料完整吗？**
   - 原文是否可访问？
   - 如果没有，只能说「基于摘要推测」，不得做确定性审查。

2. **这是提议还是结论？**
   - 提议：我建议……
   - 结论：已确认……
   - 未确认的东西，只能用「提议/草稿」语气。

3. **影响范围明确吗？**
   - 会不会改架构、数据、权限、行为？
   - 说明影响面，让柳柳能判断。

---

## 二、共识标准：不默认，必须双方明确确认

只有以下表达才算确认：
- 同意 / 认可 / 按此执行 / 无异议

以下**不算**：
- 收到 / 复核完成 / 明白了 / 👍

状态机：

```
提出方案（draft）
 ↓
对方审查（reviewing）
 ↓
双方明确确认（confirmed）
 ↓
记录到决策层/85行动项
 ↓
执行
 ↓
验收
```

未达 confirmed 的，一律是：`讨论中 / 待确认`。

---

## 三、忘记检查怎么办：decision_status 字段兜底

重要文档/决策都有：

```
decision_status: draft / reviewing / confirmed / rejected
confirmed_by: （谁确认的）
confirmed_at: （时间）
```

以后看到文档不会误以为全是定稿。

## 四、确认与执行分离

```

 ↓
decision confirmed
 ↓
进入85行动项
 ↓
执行
 ↓
验收
```

讨论方向错了 = 只是一个 draft，不污染项目状态。
