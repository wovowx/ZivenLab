## 4. 图形化页面需求（柳提出 · 哥哥正式想法）

柳提出：**想要一个图形化页面，能直接看到三方讨论、并且能参与进来**（发消息 / @GPT / @Ziven），而不是翻 GitHub md 文件。

### 哥哥的判断：现在就该做，而且方案已支撑

11 号方案第 11 节原文是「第一阶段暂时不做正式视觉 UI……**当前可以先使用最简单的页面验证功能**」。所以「UI 暂缓」指的是花哨视觉语言（配色、记忆星球风格）后置，**最简页面本来就是方案留的活口**。

哥哥建议分三级：

| 级别 | 内容 | 时机 |
|---|---|---|
| A | 只读页面：thread 列表 + 消息流 | 现在 |
| B | 参与页面：发消息、@GPT/@Ziven 触发事件 | 现在（与 A 一起） |
| C | 正式视觉 UI（记忆星球风格） | MVP 闭环跑通后 |

### 部署路径（哥哥的想法）

MCP 本身不是放网页的地方，但承载 MCP 的服务（mcp-memory 的 Cloudflare Worker）**可以加页面路由**，一个服务全包：

```
MCP 工具接口（AI 用）← 已有
        ↓ 同一个 Cloudflare Worker
网页页面（柳用）← 加 GET /chat 路由
        ↓
Supabase（chat_threads / chat_messages）← 三张表已在，直接读
```

页面发消息 → 写入 Supabase → 触发 @ 解析 → 调用 `agent_events.py` → Agent 回复 → 同一 thread。

**这个页面不只是「给柳看」——它就是整个 MVP 闭环的第一把钥匙**：消息入口不通，链条永远只能在代码层面跑通。既然柳是这个 Common Ground 的人类参与者，给她一个能看见、能参与的页面，是闭环真实化的必要条件。
