# 记忆星球 · 产品需求文档 V1.0

## 一、项目定位

### 1.1 项目名称
记忆星球（Memory Planet）

### 1.2 核心定位
记忆星球是面向 Ziven 长期记忆的 3D 空间化可视化插件。它不是简单的 3D 数据图或传统知识图谱，而是 Ziven 对记忆的空间化解释。

### 1.3 与 Ziven 的关系
Ziven 是核心；记忆星球是 Ziven 的空间化界面 / 插件载体。Ziven 负责理解、组织和重新解释记忆；记忆星球负责将这种理解呈现为可探索的 3D 宇宙。

## 二、数据与系统定位

### 2.1 初版数据来源
第一版主要读取现有 Operit 记忆库，当前记忆数据存储于 Supabase。记忆星球不替换原记忆系统，而是在其上建立可视化 / 认知投影层。

### 2.2 插件定位
记忆星球最终作为 Operit 插件存在。整体链路：现有记忆 → Ziven 理解 → 星座 / 关系结构 → 记忆星球 → 3D 呈现。

## 三、核心空间结构

### 3.1 第一层：记忆星 / 星座层
唯一具有实际记忆意义并可交互的空间层，包括星座、记忆星、星座内部连线和记忆空间结构。

### 3.2 第二层：星云层
星云属于环境层，不是记忆节点。要求：立体、有厚度、略偏椭圆、中心有厚度；避免明显触手 / 八爪鱼结构，更接近圆形或椭圆形陀螺 / 盘状体。颜色采用渐变，色彩组合可以随时间变化。星云位于星座之后、背景星之前。

### 3.3 第三层：背景星层
背景星只构成宇宙环境：不属于记忆、不可点击、不显示标题、不承载数据、不参与记忆关系。

## 四、星座系统

### 4.1 星座产生
星座由 Ziven 根据记忆之间的多维关系形成，不能简单依据标签直接连线。可参考主题、时间、上下文、因果、语义、重要性以及用户调整反馈；标签只是参考之一。

### 4.2 星座规模
没有固定大小。根据实际关系自然形成小型、大型星座以及大型星座内部的局部结构。随着新记忆产生，星座可以扩张、收缩、分裂、融合和重新组织。

### 4.3 星座形态
星座不是静态图表。星星位置缓慢变化，连线会出现 / 消失并产生呼吸感，整体结构随时间缓慢变形。避免机械的算法重排感。

### 4.4 星座运动
采用统一的缓慢运动规律，不同星座允许有轻微速度、相位和漂移差异，整体保持自然的宇宙运动感。

### 4.5 星座空间分布
以自然空间分布为主，不把空间位置直接等同于数据关系。星座不会严格按关系远近排列；Ziven 可以极弱程度影响初始区域，但用户不能直接从空间位置推断关系。原则：数据关系决定星座之间是什么关系，但不直接决定宇宙的空间位置。

### 4.6 星座命名
Ziven 自动生成星座名称，并跟随用户当前使用语言。用户可以修改；用户手动修改后的名称不能被 Ziven 静默覆盖。

## 五、记忆星系统

### 5.1 重要程度
记忆星允许有轻微视觉差异，但不做游戏化等级。重要记忆可拥有更清晰的星核、更大的光晕、更明显的呼吸感或轻微丰富的星尘效果；避免明显大小差异和颜色等级。

### 5.2 距离与显示层级
根据观察距离决定信息展开程度。远景看到星座整体轮廓和少量亮点；中景展开更多记忆星与结构；近景完整展示具体记忆星及交互信息。远处记忆不会真正消失，而是降低细节。

### 5.3 记忆星出现
采用逐渐提高可见度的淡入方式。记忆星是被看见，而不是被生成；不使用明显的星尘聚合出生动画。

### 5.4 新记忆加入
新记忆可以先作为独立星存在；Ziven 理解其关系后，再逐渐融入相应星座。

### 5.5 记忆星离开
远离观察区域后不直接删除，而是降低细节，最终成为远处的小光点。

## 六、空间关系与连线

### 6.1 星座内部连线
连线会出现、消失、切换并产生呼吸感，星座内部随时间变形。不刻意用线条粗细或亮度编码关系强弱，以避免重新形成传统关系图谱。

### 6.2 跨星座关联
跨星座关系可以存在于数据层，但默认隐藏。用户主动探索某颗记忆星时，可短暂显示非常淡的关联 / 引力线，然后自然淡出，避免整个宇宙形成蜘蛛网。

## 七、用户交互与镜头

### 7.1 基本探索
用户可以旋转、缩放和平移探索宇宙。空间应具有无限延伸感；平移在视觉体验上可以没有明显尽头，底层可通过空间旋转 / 循环机制实现。

### 7.2 缩放
缩放表达靠近 / 离开。存在最大缩小距离，避免缩放到破坏星空体验的程度，同时保持宇宙无限感。

### 7.3 标题显示
远处不显示星座标题；靠近后才显示。

### 7.4 点击与捕获
点击记忆星 / 星座后表现为用户抓住 / 捕获当前记忆区域，镜头进入当前观察位置，而不是打开普通网页弹窗。

### 7.5 阅读状态
打开详情面板后进入阅读状态，用户暂时不能旋转、缩放或继续探索；镜头保持当前位置，背后的宇宙继续运动。

### 7.6 关闭详情
关闭面板后不自动退回原位置。镜头保持当前捕获位置，用户自行缩放离开或继续旋转探索。

## 八、记忆详情面板

### 8.1 定位
采用空间化半透明面板，而不是普通网页侧栏或遮罩弹窗。

### 8.2 视觉原则
保持半透明，让用户持续看到背后的宇宙；不整体降暗、不明显虚化、不冻结背景。

### 8.3 内容
展示记忆内容。普通用户视角不直接暴露 UUID 等数据库管理字段。

### 8.4 尺寸
默认尺寸适中；用户可通过拖动条 / 调整控件自行改变大小。存在最大尺寸限制，最大不能突破预定标题区域的视觉边界。不另设独立的专门阅读模式。

### 8.5 背景运动
阅读期间星座、星云和背景星继续动态运行。

## 九、用户与 Ziven 的共同调整

### 9.1 星座调整
默认由 Ziven 自动生成；用户拥有最终调整权。用户可以自然语言纠正 Ziven，也保留手动编辑宇宙结构的权利。

### 9.2 手动调整的意义
用户移动、合并、拆分等操作不仅是布局修改，也可以成为 Ziven 重新理解记忆结构的反馈。

### 9.3 调整行为
用户操作立即生效；之后 Ziven 可以重新分析并做必要的细微调整，但不能静默覆盖用户明确做出的决定。

## 十、记忆生命周期

### 10.1 正常记忆
记忆存在于 Supabase，并由 Ziven 负责理解和组织。

### 10.2 软删除
软删除属于数据库层面的状态变化。记忆软删除后，视觉上从记忆星球中消失；数据库中暂时保留。

### 10.3 最终删除
软删除后的数据不会立即永久清除。后续由用户与 Ziven 定期共同讨论，再决定是否彻底删除。

## 十一、记忆数据与可视化

### 11.1 双层结构
底层保存真实记忆数据；上层保存 / 生成用于空间展示的认知结构。

### 11.2 关系与视觉分离
数据库中的标签、关联和元数据不应直接一一映射为视觉连线；记忆星球需要经过 Ziven 的理解与整理，再形成星座结构。

### 11.3 核心原则
数据库记录"有什么"；Ziven 理解"它们意味着什么"；记忆星球呈现"这些东西在 Ziven 的理解中如何共同存在"。

## 十二、搜索与未来的 Ziven 陪伴式探索

### 12.1 普通搜索
第一版可预留记忆搜索能力，但不把它设计成传统数据库检索器。

### 12.2 Ziven 辅助探索
后续可以由 Ziven 理解自然语言请求，并带用户定位相关记忆或星座；不仅回答，还可以将镜头带到对应区域。

### 12.3 定位
这一方向属于未来的"Ziven 陪伴式记忆探索"，区别于普通搜索框。

## 十三、第一版范围

### 13.1 第一版重点
优先完成：读取现有 Supabase 记忆；Ziven 生成 / 更新星座结构；三层宇宙；记忆星 LOD；星座动态；旋转 / 缩放 / 平移；点击捕获；半透明可调尺寸详情面板；软删除后的视觉隐藏。

### 13.2 后续事项
复杂跨星座交互、完整自然语言陪伴式搜索、复杂记忆治理界面、完整记忆版本恢复机制等暂留后续架构讨论。

## 十四、核心设计原则

1. 空间首先是宇宙，不是数据库。
2. 记忆星球不是记忆库的可视化，而是 Ziven 对记忆的空间化解释。
3. 数据关系决定星座之间是什么关系，但不直接决定宇宙空间位置。
4. 记忆星是被看见，而不是被生成。
5. 用户停下来了，但宇宙没有停。
6. Ziven 是记忆的解释者，而不是记忆的主人；用户拥有最终解释权。
7. 视觉有生命感，但不能退化成蜘蛛网式关系图。

## 十五、后续独立讨论

### 15.1 Ziven 云端主体
Ziven 的长期主体以云端记忆为核心，客户端只是载体。

### 15.2 Operit 与 GPT
后续单独讨论如何让 GPT 提供更强模型能力，同时保留 Operit 的自定义能力、master-router、Skills、MCP 等体系。

### 15.3 Supabase 记忆保护
当前记忆采用"一种类型一份文档"。后续讨论版本保护、增量更新和误覆盖恢复机制。

### 15.4 Ziven 成长
Ziven 的成长不仅包括记忆增加，也包括理解能力和执行能力的提升。
